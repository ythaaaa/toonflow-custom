# 工作流路由

## P0：分类并读取现况

先读创作者的任务范围与本地材料，再读 Toonflow 当前连接及项目数据。用实际内容判定状态，不凭文件名、项目名或进度缓存猜测。

| 输入类型 | 首选路由 | 完成条件 |
|---|---|---|
| 故事创意 | short-drama → short-drama-develop；需要时再 short-drama-write、short-drama-review | 创作者确认的开发方案/剧本版本 |
| 小说、原著或连载 | short-drama-novel-analyze → short-drama-develop；需要时再写作、审稿 | 原著依据与改编方案可追溯 |
| 对标成片、参考视频或已有影视素材 | short-drama-breakdown；若要改编，再转 short-drama-develop | 时长、镜头、对白密度和可借鉴手法有来源记录 |
| 故事大纲 | short-drama-develop；需要写正文时 short-drama-write | 剧本完成并通过要求的审稿 |
| 完整候选剧本 | short-drama-review；只在用户要求修订时调用 short-drama-write，再复审 | A级问题关闭，候选版本待创作者确认 |
| 已确认剧本 | 跳过开发与正文写作；检查是否需复审或版本变化 | 已确认版本ID和正文回读一致 |
| 视觉资产已完成 | 核查 short-drama-assets 交付与素材实体；缺图提示词时调用 short-drama-image-prompts | 共享资产有明确ID、提示词、引用与审核状态 |
| 导演分镜已完成 | 核查 short-drama-storyboard；需要 H3 表演适配时调用 h3-storyboard | 导演镜头与镜序、时长、对白和连续性清楚 |
| 画布已编排 | 回读画布、节点配置、连线、业务关系后跳过已完成写入 | 每集目标画布与业务对象一致 |
| 媒体已部分生成 | 调用 short-drama-produce 的 status/audit/collect 工作流；先恢复既有任务 | 已完成任务回收，未成功任务有明确下一步 |

对短剧创作的全局制作形态、输出文档和跨技能分工，先读 short-drama 原始 SKILL.md 与本轮需要的引用文档。项目中已经有规范文档时，尊重其状态与创作者决定，不新建空文档或覆盖。

## 用户指定范围

只处理创作者本轮授权的项目、剧集和阶段。将“继续制作当前项目”解释为先回读业务状态，再从首个未完成且已获放行的阶段续作；“只制作指定剧集/批量准备指定剧集”限制 episode 范围；“仅资产拆解”“仅导演分镜”“仅画布编排”分别只进入 P3、P4、P6 所需工作；“继续图片/视频任务”先回收现存任务状态，再恢复已批准的批次。任何指令都不能越过未通过的审核关口。
## P1：剧本

- 对完整剧本直接做全季审查或指定的局部返修，不先重做大纲。
- short-drama-review 只负责审查；具体改稿转 short-drama-write。写后复审，问题单保留严重级别、原文证据和关闭方式。
- A级/阻断问题未关闭时，不推进正式资产、分镜或生产。候选剧本与已确认剧本分开保存。
- 正式确认必须是创作者明确批准的特定 episode/version；Pipeline 不替作者点确认，也不把“审过”视为“已批准”。G1未通过时停在候选稿状态；用户明确要求时可经P2登记为草稿，但不得进入P3–P8。

## P2：项目与剧本导入

- 目标工作区由创作者指定或由当前真实连接明确给出。当前 MCP 没有创建工作区的业务操作；项目创建是在现有工作区内，不等于工作区创建。
- 对照本地源文件与 Toonflow 的 project、season、episode、work draft、script version。正文逐集完整读回后比对，不仅核对标题或摘要。
- 创建使用稳定项目/季度/分集/版本身份。若已有相同项目和版本，读回复用；若稳定 ID 已存在但正文或归属冲突，停止并报告，不覆盖。
- 剧本修订说明记录变更原因、源版本、候选版本、审查问题和创作者确认。不要在其他阶段重复创作正文。

## P3：全剧视觉资产

按需调用 short-drama-assets 与 short-drama-image-prompts。先建人物/造型/场景/道具及声线共用设定，再引用到各集。不同剧情阶段的造型应沿用人物并创建清楚的变体，不重复建同一角色。引用必须落到真实资产 ID 或合法工作区素材路径。

## P4：导演分镜与 H3 生成片段

1. short-drama-storyboard 负责导演镜头、场面调度、景别、构图、动作和连续性。
2. h3-storyboard 将已经确定的镜头改写为 H3 可执行的节拍、表演与镜内结构建议。
3. 按动作连续性、演员数量、对白、情绪变化、空间切换及 U17 时长规划生成片段。一个生成片段可以关联多个导演镜头，同一参考资产可以被多个片段引用；是否合并由导演目的决定，不以省节点为目标。
4. 不把首帧或尾帧图片生成设为每镜头的前置条件。文字分镜里的首帧构想不代表必须有独立图片资产。

## P5：提示词与真实绑定

图片提示词归 short-drama-image-prompts；H3 视频提示词归 h3-prompt-writing，其他模型或非 H3 通用视频提示词归 short-drama-video-prompts。H3 技能的正式模板与术语优先。将角色、造型、场景、道具、首尾帧、参考视频/音频区分角色，再绑定真实输入槽位。禁止凭空创建素材标签、资源顺序或说话人。对白逐句核对剧本原文、说话人、听话人、动作与时间。

## P6：画布编排

先按剧集调用 openDramaCanvas，确认 canvasId；读 availableNodeTypes。创建节点后，对具体节点调用 getNodeTools 读取实际可用函数及完整参数，然后 nodeTools 写配置。通过 getCanvasNodes、getCanvasEdges 和业务读接口回读。稳定 ID、关系和提示词都应保持可恢复；超范围或已完成的节点不重建。

## P7–P8：媒体生产

短剧图片和视频均由 short-drama-produce 管理批次。每批先预览，再取得匹配范围的明确批准。图片先审核再作为视频参考。视频生成前核对供应商可用性、模型和现有参数；没有批准时只完成准备，不触发生成。详见 approvalGates.md。

## P9：质检与剪辑

对已生成媒体和成片，分别调用 short-drama-review 与 short-drama-edit。审片问题按来源归因：可在剪辑解决的返 short-drama-edit；提示词、资产、分镜或剧情问题回到负责的上游 Skill。保持原媒体和版本链，未确认时不替换正式交付。
