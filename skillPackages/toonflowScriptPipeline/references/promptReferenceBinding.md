# H3 提示词、对白与参考绑定

## 官方 H3 输出结构

每次实际编写前读取 h3-prompt-writing 原始 SKILL.md 和其对应参考文件。该 Skill 定义的 H3 提示词模式包括 T2VA、I2VA、FL2VA、L2VA 及 Full-Reference；不要为了统一全管线而改写其格式。

Full-Reference 模式的六节顺序为：

1. subject_definitions：定义人物、场景、服装、道具、参考帧、视频或音频，并说明身份和来源。
2. summary：标明真实任务类型及主要参考关系。
3. retention_analysis：逐项说明参考内容在输出中的保留、转移或引用方式。
4. detailed_description：按播放时间写镜头、动作、构图、表演、对白与声音。
5. overall_soundscape：全片环境与动作声音。
6. non_diegetic_music：角色听不到、仅观众听到的配乐。

遵循 h3-prompt-writing 当前规范的语言要求、标点和模式开头。对白与画面可见文字保留剧本原文；不翻译、润色、删节或替换台词。不要把完整对白重复到 soundscape 或配乐栏。

其他模式按官方对应模板输出。若当前生成节点仅存储一个提示词字符串，保留 Skill 定义的字段结构在该字符串内；实际参数键由节点 schema 决定。

## H3 标签与 Toonflow 输入标记是两套编号

官方 H3 标签如 <Subject N>、<Picture N>、<Video N>、<Audio N> 是提示词语义标签。视频节点并不会因为文字中出现这些标签就创建或连接素材。

Toonflow remote-videoGenerationNode 的实际提示词还支持 {{ref N}}。该编号指向当前视频节点 input reference list 的一基序号，和 H3 按素材类型编号的 Picture/Video/Audio 不是同一套编号。一个提示词里的 Picture 1 可能实际绑定到 {{ref 2}}，尤其当图片前面还有文本或其他类型输入时。

建立逐项绑定表，把每个 H3 标签映射到对应的 {{ref N}}、来源节点/资产、输入顺序、模态、用途和镜头。写入前读取 getCanvasEdges 与节点 data.referenceOrder；通过实际端口、getConfig 返回的模型能力和节点提示词输入格式确认映射。若有 referenceOrder，按该顺序核对；若无，检查当前节点实现如何从实际输入边构造参考列表。只有确认实现确实按该边顺序组装输入后，才能据此编号；getCanvasEdges 的返回顺序本身不能证明输入顺序。setPrompt 写入的 {{ref N}} 必须能对应真实可解析的输入项。缺少引用、顺序无法从实际画布及插件规则中确定或模型配置不匹配时停止并修正；不要把没有边的标签当成已绑定。

## Reference 标签到真实素材

每个标签必须能追溯到实际参考输入：

| 提示词引用 | 真实绑定要求 |
|---|---|
| 人物/场景/造型/道具 Subject | 已有资产 ID；若模型输入需要图片，还要有真实图片节点、路径及顺序 |
| Picture | 真实图片资产和视频节点上的图片输入槽；说明作为首帧、尾帧、关键帧还是普通参考 |
| Video | 真实参考视频资产和对应视频输入槽；不能把普通生成结果或想象文件写成绑定 |
| Audio | 真实参考音频资产和对应音频输入槽；人物声线身份仍需稳定映射至说话人 |

写视频节点前，先从节点实际 getConfig/setConfig schema 读取参考数组和模型槽位，再通过真实画布边连接。每个 reference 标签都应在绑定表中记录：

- 标签与实际 {{ref N}}；
- assetId、素材路径或源节点 ID；
- 模态、用途及准许控制的信息；
- 排序编号和目标节点输入槽；
- 关联的导演镜头 ID；
- 是否为审核通过素材；
- 来源版本及连续性限制。

用 getCanvasNodes 读 ports/data/referenceOrder，用 getCanvasEdges 确认边，用节点 getConfig 读取当前模型能力与参考上限。若当前插件没有将顺序稳定地映射到标签，先停下来说明能力缺口；不可仅靠在提示词中写 Picture 1、Picture 2 假装接入成功。

当前 H3 U17 限制为最多9张参考图片、1个参考视频、3个参考音频。按实际模型上限排序和校验；同一资产可以被多个视频节点引用，不代表可在同一节点中重复任意添加。节点变更后重新读取列表与边，确认引用次序和归属。

## 对白归属核对

每个片段先建对白核对表，再写入 H3 提示词：

| 核对字段 | 检查内容 |
|---|---|
| 台词来源 | 逐字匹配具体剧集、已确认的剧本版本和原剧本行；保留台词及标点 |
| 说话人 | speakerId 与 Toonflow characterId 稳定映射；再与导演镜头角色和提示词中的发言人核对，不以镜头中心人物猜测 |
| 听话人/交流对象 | 标明被直接称呼、接听电话或接收信息的角色及 ID；无单一听话人时标明交流类型和原因，不猜测 |
| 表演动作 | 记录说话人的镜头内表情、动作、持物状态和起止位置；不得把未核实的动作当成剧本事实 |
| 听者反应 | 写明镜内/镜外、可见反应及其时间；没有明确反应时写“未安排可见反应”，不凭空补对白 |
| 片段时间轴 | 标明对应 shotId、镜头内对白起止时间、停顿/反应及切点，并与片段本地时间和总时长核对 |
| 发声类型 | 区分面对面交流、独白、电话/通讯、画外音及多人同时发言，按对应来源和收听对象标注 |
| 模式标签 | H3 所需的角色标记/对白语法有效，台词本身没有被改写 |
| 参考影响 | 声线、角色图、动作/场景图各控制哪些属性，哪些属性不得改变 |

对白归属按发声类型记录，不要求每句都配置单一听话人：

- 面对面台词标明交流对象；确实没有可确认对象时写“无明确听话人（原因）”。不能将未确认的推测写成确定对象。
- 独白标明自言自语、内心独白或面向观众等实际形式，并写明镜内外发声状态；无交流对象时明确标记。
- 电话/通讯标明本端与远端说话人、双方 characterId、当前发声端、收听端及镜内/镜外状态。
- 画外音标明稳定的声源身份、是否属于当前画面人物，以及画面中是否存在交流对象；不能把画面中心人物自动当作发言人或听者。
- 多人交流按每个发声事件分别列出 speakerId、参与角色和对象；多人同时发言时列出全部 speakerId 和共同对象，不强行指定单一听者。

按“原剧本行 → 人物 ID → 导演镜头 → H3 提示词时间线”逐句核对，保证一一对应。说话人交换、台词遗漏/增写、角色 ID 冲突、发声类型误标、参考绑定错误或时间轴无法容纳对白与反应时，将对应 videoSegment 标记为待修并阻断 P8；问题关闭前不提交该片段生成。

逐句对照剧本、说话人、听话人、语义、动作及提示词时间轴。发现角色对白交换、给画外音错配角色、把听者反应写成发言，或提示词添加剧本不存在的对白时，返回分镜/剧本责任技能修正。不能把 Dialogue ownership 检查简化成“有角色名”。

## 连戏与提示词改动复核

每次编辑提示词、镜头组或参考顺序，检查：

- 人物身份、发型、服装版本和声线稳定；
- 站位、视线轴、持物手、道具状态和景别切点与前后镜一致；
- 图片参考体现的是身份、空间还是具体时刻，未误当作另一种用途；
- 所有片段的镜头顺序和时长覆盖分镜，且没有遗漏必须呈现的动作或对白；
- H3 官方格式与当前节点真实可解析格式同时成立。

h3-storyboard 的实拍经验应标为项目经验、外部经验或未验证推论。只有已核验的接口/字段/时长限制才列为硬约束；具体镜头表现建议需在输出审核结果后再修正。
