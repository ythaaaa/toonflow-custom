# 断点续作、异常恢复与验收

## 状态来源与轻量进度文件

以 Toonflow 已读回的业务状态为准：projectId、seasonId、episodeId、剧本工作稿/版本及确认状态、人物/造型/资产、sceneId、shotId、videoSegmentId、画布节点/边和媒体任务状态。每次开始或恢复前重新读取这些实体；本地 Pipeline 状态文件只用于定位上次做到哪里。

只有当业务对象字段不足以保存跨阶段信息时，才在工作区使用 workspaceFiles 写 pipelineState/<projectId>.json。首次写入前检查同名目录/文件；新建用 exclusive，已存在时读回确认 projectId 后才更新。存储 UTF-8 JSON 的 base64 数据，写后再读回核验。不要保存完整剧本、认证信息、访问令牌或大体积媒体。

建议结构：

- schemaVersion、updatedAt、projectId、projectName、seasonIds；
- episodes[]：episodeId、sourceScriptRevision/versionId、scriptStatus、contentHash、assetIds、sceneIds、shotIds、videoSegmentIds、canvasId、nodeIds、edgeFingerprints；
- stages：P0–P9 的 notStarted / preparing / waitingApproval / complete / blocked 状态及证据 ID；
- approvals[]：gate、approvedScope、sourceVersion、approvedAt 和批准内容指纹；
- pendingIssues[]：级别、所有者 Skill、相关 ID、下一步；
- lastFailure：阶段、接口名、稳定 ID、错误类别、请求是否已提交、可恢复动作。

只更新本项目状态，不清理旧文件。记录业务对象的 ID 与摘要即可，不复制正文。文件与 MCP 不一致时，以业务数据为准，先修正进度记录。

### 画布 ID 断点恢复

- 每次恢复以 `getAppState`、实时 `getCanvas`/画布列表读取出的 ID 为准；禁止按文件名、项目/剧集 ID 或历史状态拼接、猜测 canvasId。
- 通过画布节点的 `dramaBinding.projectId`、`episodeId` 及对应业务对象核实画布确属目标项目和剧集。画布 ID 相同但绑定不符，或目标画布无法唯一确认时，停止并报告，不写状态、不建新画布。
- 状态文件 canvasId 与实时对象不一致时，先确认目标画布已存在且归属正确；随后只修正该项目 Pipeline 状态记录。不得为修复指针而调用会创建/同步画布的流程或重复建档。
- 状态写入后必须用 `workspaceFiles` 重新读取，核对 projectId、episodeId、实时 canvasId；并回读目标画布节点/连线，确认对象集合归属仍一致。

## 依赖变化与局部失效

- 剧本候选版本/正式版改变：标记其依赖的资产、分镜、对白、提示词和媒体需要检查；比较变更影响后局部返修，不自动重做全剧。
- 人物/造型/场景/道具资产改变：找出引用该 assetId 的集、镜头、视频节点与已生成结果，只重审受影响范围。
- 导演镜头/对白改变：检查对应片段分组、时间线、提示词和媒体；不要影响无关片段。
- 参考素材顺序、H3 模式或参数改变：重新审核提示词与节点配置；批准失效范围需精确标注。
- 画布或节点缺失：先确认是否能从业务数据重新同步；保留用户画布布局和非业务节点。

状态变化要写清楚依赖源 ID、失效的下游对象和待重新审核范围。不要因一个对象改变而无条件重做整集/全季。

## 中断与错误恢复

1. 重新调用 getAppState，检查连接、工作区和激活画布是否仍为目标。
2. 通过业务读取接口和实时画布工具查找已写入对象，记录已完成、部分完成和缺失项。
3. 有稳定 ID且读回内容一致的操作视为已完成；ID 存在但数据冲突时停止，不换 ID 重复创建。
4. 对 applyDramaBatch 读取已完成/失败/未执行项；它没有整体事务回滚。仅从失败操作恢复。
5. 节点或连线调用失败后先读 getCanvasNodes/getCanvasEdges，再幂等重试。刷新/重开后再次回读以确认持久化。
6. 生成任务如果可能已经提交，先用 short-drama-produce 的 status/audit/collect 路径回收任务或结果；只有确认未提交或已安全结束才考虑新任务。不得盲目重提或绕过失败状态。
7. 写状态文件失败时如实保留恢复线索；不能声称业务写入成功，也不能用直接改画布/数据库文件的方式补偿。
8. 不通过删除、软删除或回滚历史数据清理失败痕迹。

状态文件指向旧画布或无效 ID 时，按“画布 ID 断点恢复”流程查找和核实现存画布。不得仅因状态指针不匹配而调用新建/同步画布；找到匹配的现存画布后，只修复状态记录并回读。

## 隔离验收清单

验收使用隔离工作区中的新测试项目和短剧，不读写正式制作项目作为测试目标。测试阶段不得调用图片/视频生成接口、AutoDL、GPT供应商或其他付费媒体 API。

1. 发现完整剧本后，路由跳过重复开发/写作；只读检查版本与审稿状态。
2. 已导入的剧本和项目重复运行时保持同一稳定业务 ID、无重复分集/版本/节点。
3. 候选稿未获确认时保持草稿，不调用正式版本确认接口，不进入需确认的生产关口。
4. 已确认版本能够继续资产/分镜阶段；只检查接口目标和读取状态，不生成媒体。
5. 验证 Skills 路由指向真实存在的 short-drama 与 H3 Skills；若会话不能实际触发 Skills，记录该限制。
6. 真实 MCP 将多个 shotId 关联到一个 videoSegmentId，并读回完整关系。
7. 同一真实图片资产节点可连接多个视频节点；读回节点、端口、边和参考顺序。
8. 存在未创建首帧图的导演镜头，仍能建立视频片段和合法参考绑定。
9. 用含错位说话人的隔离文本进行对白表校对，确认逐句校验会阻断该问题；不得写入正式脚本。
10. 以相同稳定参数重复创建项目资产、片段、节点和连接，读回数量不增加。
11. 在业务写入中途停止，再按真实数据恢复；确认从首个缺失对象继续。
12. 无批准时不调用任何生产工具，不出现媒体生成任务或资源消耗。
13. 将新 Skill 安装在当前 Codex 实际扫描目录，核对 frontmatter、UI 元数据和引用路径。自动技能列表若为会话启动快照，需在新 Codex 会话验证发现/调用；当前会话未刷新时只报告“已安装，待新会话验证”，不可宣称通过。
14. 画布 ID 与状态记录不一致时，按实时 MCP 读取的画布 ID及项目/剧集绑定进行只读归属核实；若匹配画布已存在，仅更新并回读状态指针，验证没有创建重复画布。
15. 对每个隔离 H3 片段回读配置总时长、shotId/镜序和本地时间分配，核对动作、原文对白、反应停顿、转场及剪辑预留；验证没有未解释的空白/重叠或不足以容纳台词的区间。
16. 对每句隔离对白核对剧本来源、speakerId/characterId、听话对象或正确的独白/电话/画外音/多人发声类型、导演镜头、表演动作、听者反应和片段内时间位置；注入错配、遗漏或错误角色 ID 的静态样例应阻断对应片段进入生成。验收不调用媒体生成。

验收报告分别标注：真实 MCP 写入/回读、纯文档/人工逻辑校验、未执行的媒体任务、当前 Codex 自动 Skill 发现状态。文件存在或构建通过不等于功能验收。
