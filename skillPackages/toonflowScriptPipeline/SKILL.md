# Toonflow 短剧全流程制作

将本 Skill 用作流程总调度器。复用已有 Drama、H3 Skills 和 Toonflow MCP；不重写它们的规则，不重复已完成的制作阶段，不扩展用户指定范围。

## 每次运行的顺序

1. 识别用户明确要求的项目、集数、阶段、审核状态和禁止事项。仅处理该范围。
2. 读取当前可用的相关 Skills 原始 SKILL.md 及本轮会用到的引用文档，再选择路由；不得仅依据技能名称猜测行为。不要复制原 Skill 的全部规则。
3. 先用 Toonflow MCP 读取连接、工作区和实际业务数据；再对照本地进度记录。以实际 Toonflow 回读结果为准。
4. 按 P0–P9 路由；已完成阶段只读检查后跳过，候选稿或未批准媒体任务在对应审核关口停止。
5. 每次有写入时保存稳定 ID，随即回读校验；若执行中断，先查现状再恢复，不盲目重放。

## 阶段路由

- P0 项目识别与状态检查：识别创意、原著、梗概、候选/正式剧本，以及已完成资产、分镜、画布或媒体的进度。按需读项目、剧本版本、视觉资产、场景、导演镜头、视频片段、画布节点和连线。
- P1 剧本开发、写作与审稿：依素材状态调用 short-drama、short-drama-novel-analyze、short-drama-develop、short-drama-write、short-drama-review。完整剧本不重做全季大纲或正文。A级问题未关闭不得进入正式制作；候选稿保持草稿，G1确认未通过时不得进入P3–P8，也不得设为正式版本。用户明确要求时，可先通过P2导入为草稿。
- P2 Toonflow 建档与剧本导入：使用当前工作区内现有 MCP 业务接口创建或复用项目、季度、分集和草稿版本。逐集回读完整正文并核对来源版本；不自动覆盖、确认或归档既有版本。
- P3 全剧视觉资产：按需调用 short-drama-assets 与 short-drama-image-prompts；优先复用共享人物、造型、场景、道具和声线设定，登记跨集引用。
- P4 导演分镜与生成片段规划：先调用 short-drama-storyboard 完成影视表达，再调用 h3-storyboard 适配 H3 表演与节拍。导演镜头与视频生成片段是不同对象；多镜头可归入一个片段，但须有导演依据。首帧、尾帧图均按需创建。
- P5 提示词与参考绑定：图片提示词由 short-drama-image-prompts 负责；H3 视频提示词按 h3-prompt-writing 的实际模式和格式编写。将每个提示词中的参考标签映射到真实资产、节点、顺序和模型输入，不允许只写未绑定的标签。
- P6 无限画布：使用真实 Toonflow MCP 画布工具；先确认浏览器连接、工作区、画布和 episode 归属，读取可用节点类型及每个节点的实际函数 schema，再创建、连接、布局、回读。禁止直接编辑画布 JSON。
- P7 图片生产：按需调用 short-drama-produce。先向创作者展示本批范围、提示词/参数、供应商和输出；得到针对该批的明确批准后才提交生成。生成结果进入审核，未通过不得供视频节点引用为已审核资产。
- P8 H3 视频生产：按需调用 short-drama-produce。核验参考资产、提示词、对白说话人、时长、参数和 AutoDL 可访问性；仅在创作者明确批准对应任务/批次后提交。沿用供应商任务状态，失败时先查远程任务与现有产出再恢复。
- P9 成片质检与剪辑：按需调用 short-drama-review、short-drama-edit；将无法靠剪辑补救的问题退回相应上游阶段，并保留素材与版本关系。

完整路由、阶段入口和“跳过/继续”判定见 [references/workflowRouting.md](references/workflowRouting.md)。

## 资产生产与连续执行

- 全季资产规划是供后续复用的需求清单，不代表全季生图；仅生成当前制作范围实际需要的图片。
- 已有合格且通过审核的资产优先复用。每次生图前检查项目已有资产及媒体结果，避免重复生成。
- 不为补齐资产清单或填满 H3 参考数量生图。没有明确制作需要时，不生成额外人物角度、服装变体、普通道具图或首尾帧。
- 按素材实际用途选择画幅，不把视频画幅机械套用到所有角色、场景和道具设定图。
- 已明确批准的审核阶段，在批准范围和内容未变化时继续有效，不重复询问。普通制作步骤按既定流程连续执行，不要求创作者反复发送“继续”；需要创作者批准的媒体生成仍须在对应关口等待明确授权。

## 审核关口

1. 剧本正式确认。
2. 全剧视觉设定与导演制作方案确认。
3. 画布编排与图片批次批准。
4. 图片质量审核与视频批次批准。
5. 成片验收。

只询问尚未获得批准的关口。已批准范围未变时可沿用；剧本、资产、镜头、提示词、模型参数、输出范围或成本变化时，先重新展示受影响内容并取得新批准。不得代替创作者确认剧本或生成任务。细则见 [references/approvalGates.md](references/approvalGates.md)。

## 统一边界

- 创作者明确范围与限制优先。保持现实主义和原作核心价值，不擅自爽剧化或删戏。
- 确定的接口/模型约束与影视创作判断分开记录；未经证实的第三方经验只能作建议，不能伪装成官方能力。
- 媒体生成会产生外部任务或资源消耗；未获针对范围的明确批准，不调用任何生成接口。
- 不删除工作区文件、不覆盖用户成果、不重设已有制作状态。发现冲突、跨项目引用、工具缺失或审核未过时暂停相关写入并报告。
- 不自动设置正式剧本版本。建立候选版本与正式版本的显式关系。
- 本地 Pipeline 状态只是恢复线索，不是业务事实。续作前必须读取 Toonflow 的真实数据。
- 如当前 Codex 会话未加载所需 Skill，读取该 Skill 的原始文件按其规则执行，并如实说明无法验证自动技能调度；不虚构工具调用。
